# QQ 官方机器人接入

QQ 官方通道使用腾讯 QQ 开放平台和 `@tencent-connect/qqbot-nodejs`。SDK 负责 Token、心跳、会话恢复和重连；DSH Superagent IM 负责授权、任务流和回复。

## 与腾讯独立聊天插件的区别

本仓库已包含 QQ 来源，不需要同时运行 `@tencent-connect/dsh-qqbot`。后者直接创建普通 Harness 对话，本仓库则把 QQ 消息交给 Superagent 的授权、评估、工单和执行器流程。

同一个机器人切换到本仓库时，先停用独立聊天插件，再启用这里的 QQ 来源，避免两个 WebSocket 连接争用同一个账号。独立插件保留的扫码凭据可用于填写这里的 AppID 和 AppSecret，但不要把密钥复制到聊天或仓库中。

群号、机器人资料卡上的 QQ 号码和 API OpenID 不能混用。机器人身份应通过官方 `/users/@me` 接口核实；群与用户 OpenID 来自该 AppID 的消息事件。群里的 `GROUP_AT_MESSAGE_CREATE` 即使不携带显式 mentions 列表，也按 @机器人处理。

独立聊天插件的 `/bot-ping`、`/bot-me`、`/model` 等命令不是本仓库的控制命令。切换后在 Superagent 的「来源」检查连接状态，在「触发」核对收到的消息；请求是否创建工单由「设置 → 策略」中的规则和授权名单决定。

## 准备

1. 在 QQ 开放平台创建机器人应用，取得 AppID 和 AppSecret。
2. 按开放平台要求完成测试或发布配置，并把机器人加入要接收消息的群。
3. 确认机器人的 OpenID。它用于识别 @ 和过滤机器人自身消息，不能用普通 QQ 号代替。
4. 在 Cordis 配置中启用 `dsh-superagent-im-qq-official`，重启 DSH。
5. 在面板「设置 → 消息来源」填写 AppID、AppSecret、机器人 OpenID、接收的群和私聊开关。
6. 在「策略」中按 `AppID:用户OpenID` 添加能发起工作的用户。

群可以选择「仅 @」或「全部消息」。「全部消息」只表示消息会进入评估边界，是否创建工作仍由策略和接单模式决定。未列出的群默认不接收，也可以改为只接收 @。

## 安全边界

- AppSecret 只用于官方 SDK 鉴权，不写入 Trigger、Thread、Channel 地址、链接或执行器环境。
- 使用最小权限，只开通实际需要的群消息、私聊和回复能力。
- 不要把 AppSecret 写进仓库、示例、日志或聊天消息；泄漏后立即在开放平台轮换。
- 自动回复受 QQ 平台频率、被动回复时限和目标状态约束；限流会重试，永久失效目标会停止投递。
- 本项目是社区项目，不是 DeepSeek 或腾讯的官方产品。

## 停用与排障

在消息来源设置中关闭该 Source，或在 Cordis 中禁用 `dsh-superagent-im-qq-official`。关闭后新消息不再进入，待发送回复会等待或按目标状态丢弃。

- 一直显示连接中：检查应用是否已发布、AppID/AppSecret 是否匹配，以及服务器能否访问 QQ 开放平台。
- 收不到群消息：检查机器人是否已入群、群是否列入接收范围、是否要求 @，以及用户是否在策略名单内。
- 能收不能回：检查平台权限、被动回复时限和健康状态；不要把真实密钥贴到问题报告中。
- 重复事件不会重复创建任务；稳定消息 ID 会在核心入口去重。

真实账号验收应在测试群完成：先发一条未 @ 消息确认被过滤，再由名单内用户 @ 机器人发起一个无副作用请求，最后关闭 Source 确认不再接收。
